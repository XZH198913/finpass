# 4c 前基线：Q1–Q7（以 `docs/baseline-4b-cli.txt` 为准）

试用视角：没读过 README、不知道 FinPass 内部结构的人，跑完一条命令后看到什么。
基线时间：2026-11-05，代码处于 4b 封版 + 4c 未实施状态。

## Q1. 是否还会被问「问题 N 个，请逐题回答」？

**没有被逐题问。** 默认 `--interactive none`，终端只有一行统计：

```
问题 6 个 | 规则 date_format, duplicate_key, missing_token, ohlc_contradiction, unit_ambiguity
```

但注意：这里「没问」是通过 `resolve_auto=True` 自动收尾实现的——6 道题里 3 道被自动改、
3 道被打标跳过，用户在这一步**既没被问，也没有机会介入**。终端没有一句「有 3 道题我没动，
需要你处理」。

## Q2. 是否有自动决策的日志？每一条在说什么？

有 6 行 event 日志，每行只说四件事：规则名、`event_id`、影响行数、fix/flag：

```
[duplicate_key]     event_id=12a199cf… 影响 1 行 决策=flag
[missing_token]     event_id=24c1a0d5… 影响 1 行 决策=fix
[missing_token]     event_id=ae73ae4a… 影响 1 行 决策=fix
[unit_ambiguity]    event_id=82926e4a… 影响 1 行 决策=flag
[date_format]       event_id=d3c16319… 影响 1 行 决策=fix
[ohlc_contradiction] event_id=fe5da62f… 影响 1 行 决策=flag
```

**没有**以下三类说明（逐条核对过）：

- 类型转换：无（`成交额_元` 从文本转 float64 这件事，终端一个字没提）
- 填充说明：无（「`收盘价` 的 `--` 填成了空值」看不到）
- 单位归一：无（`12000000` → `1200.0` 的换算与系数，看不到）

## Q3. 日志是否可读？没读过 README 的人能否复述引擎做了什么？

**不能。** 能看出来的只有「有 6 条规则动了各 1 行」。看不出来的有：

- 改的是**哪个单元格**、改成了什么值；
- 为什么判定它有问题（阈值 0.0001？边界？格式？）；
- `flag` 是什么意思（打标保留？还是失败了？）；
- 32 位 `event_id` 对用户是纯噪音，它的价值在于「能对回产物」（内部视角）。

一个没读过 README 的人读完这段输出，最可能的理解是「它跑了 6 个检查，3 个修了，3 个没修」——
「没修的 3 个要不要我管」这一点无从得知。

## Q4. 日志里有没有「检查 N 条 / 触发 M 条 / 未动 K 条」汇总？

**有，且是第一行之后立刻出现：**

```
[summary] 检查 5 条规则 / 触发 5 条 / 未动 0 条 / 未答 0 条
```

补充观察：这里 N=5 是 profile 声明的规则条数，M=5 是命中的规则**条数**（不是问题数 6）。
末尾还有 `改动 3` / `flag 3` / `未问 0（来源：（无））` 三行，算是把「修了几条 / 标了几条」补上。
但「未动 0 条」的语义是「没有哪条规则完全没命中」，不是「没有未处理的题」——两者容易混。

## Q5. 退出码是多少？

**2**。符合既定口径（有 flag 未清 → 2；全清 → 0）。终端最后一行也自报了：`退出码 2`。

## Q6. 用户手里有什么产物？能看懂吗？

`out/baseline-4b/` 下 7 个文件：

| 产物 | 用户能直接看懂吗 |
|---|---|
| `clean.csv` | 能（但要自己逐格对比才知道改了什么） |
| `diff.html` | 能（唯一的可视化，六色标出改动格） |
| `passport.json` | 半能（字段名如 `counts` / `output_file_sha256` 需要背景） |
| `changes.parquet` | 不能（需要 pandas/parquet 工具） |
| `events.jsonl` | 不能（机读事件流） |
| `report.before.json` / `report.after.json` | 半能（行数/空值/重复数/dtypes） |

结论：**「看得懂」的只有 1 个半**（`diff.html` + `clean.csv`），其余要工具或背景知识。

## Q7. 用户要复核引擎做的决策，看哪里？要不要读 JSON？能不能只看终端？

- 看 `changes.parquet`（逐格 `row_key / col / before / after / change_type / rule_id`）最完整；
- 或看 `diff.html`（可视化，但只有位置与颜色，没有「为什么」）；
- 或看 `events.jsonl`（决策事件，含 action / params / 前后数据指纹，机读）；
- **只看终端不够**：终端只有 `event_id` 与行数，没有任何 `before → after`。
  要复核必须落到产物，而产物里能看懂的只有 `diff.html`。

## 基线小结

| 项 | 现状 |
|---|---|
| 被逐题问 | 否（但靠「自动收尾」，不是靠「引擎会自己决定」） |
| 自动决策日志 | 有 event 行，无「改了什么、为什么」 |
| 日志可读 | 否（外部读者视角） |
| 汇总 | 有 N/M/K + 改动/flag/未问 |
| 退出码 | 2（有 flag） |
| 产物可读性 | diff.html 最佳，其余需工具 |
| 复核路径 | 必须读产物，终端不够 |
